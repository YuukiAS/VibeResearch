# VibeResearch 0.13.0 Session-Oriented Research Kernel Plan

## Purpose

This plan implements `docs/todos/TODO-v15.md`. 0.13.0 establishes a shared
research kernel that multiple Codex sessions can read and update through files
instead of relying on one session's chat context.

The release must stay generic. It should define a reusable file protocol for
research state, evidence, negative memory, open debts, and session-role
boundaries without embedding CARE-specific project logic.

## Scope

0.13.0 will add:

- A `.vibe/kernel/` state surface with `PROJECT_KERNEL.md`,
  `PROBLEM_STATE.md`, `FAILURE_SIGNATURES.md`, `OPEN_DEBTS.md`,
  `NEGATIVE_MEMORY.md`, `SESSION_PROTOCOL.md`, and `EVIDENCE_LEDGER.jsonl`.
- Initialization and verification helpers that create missing kernel files and
  refuse protocol-sensitive actions when required files are absent.
- Append-only evidence ledger records with source, timestamp, session role,
  artifact pointer, evidence type, belief update, and next action fields.
- Role-boundary validation so one session cannot claim planner, reviewer,
  executor, and reflector duties for the same cycle.
- CLI commands under `vibe kernel` for init, status, evidence recording, and
  protocol checks.

## Commands

Add generic CLI surfaces:

- `vibe kernel init`
- `vibe kernel status`
- `vibe kernel record-evidence`
- `vibe kernel check-protocol`

## File Protocol

Kernel files live under `.vibe/kernel/`. Markdown files are human-editable and
must include enough structure for a new session to recover the project goal,
problem state, failure signatures, open debts, negative memory, and role
protocol. `EVIDENCE_LEDGER.jsonl` is append-only machine-readable evidence.

Each ledger record must carry:

- `created_at`
- `session_role`
- `source`
- `artifact`
- `evidence_type`
- `belief_update`
- `next_action`

## Gates

- A status/check command must report missing core files and return a failing
  protocol status unless the caller explicitly initializes the kernel.
- Ledger evidence without an artifact pointer, evidence type, belief update, or
  session role must be rejected.
- A single `session_id` cannot claim all four closed-loop duties:
  `plan`, `review`, `execute`, and `reflect`.
- Protocol checks must surface role-boundary violations without mutating
  scientific state.

## Tests

Add tests for:

- `vibe init` and `vibe kernel init` create the required kernel files;
- a new session can recover kernel status from files;
- missing core files produce a failing protocol check;
- evidence ledger entries are append-only and trace artifact pointers;
- single-session closed-loop role claims are blocked.

## Commit Criteria

Before committing 0.13.0:

- update version metadata, `CHANGELOG.md`, and README docs as needed;
- run targeted kernel tests;
- run full pytest;
- stage only 0.13.0 files and commit.
