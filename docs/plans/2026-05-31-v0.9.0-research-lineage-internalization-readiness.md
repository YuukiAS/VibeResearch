# VibeResearch 0.9.0 Research Lineage and Internalization Readiness Plan

## Purpose

This plan implements `docs/todos/TODO-v7.md` as a generic framework capability:
VibeResearch must distinguish calling an external repository from owning an
internal framework, and it must record the evidence, lineage, decisions, risks,
and stage gates that justify any move toward internal implementation.

No project-specific CARE model, metric, dataset, or challenge logic belongs in
this release.

## Scope

0.9.0 will add:

- A research lineage registry for external assets, internal hypotheses,
  internal design proposals, implementation candidates, and experiment evidence.
- Internalization levels and policy-controlled transition checks.
- A structured internalization decision and framework proposal artifact.
- A readiness gate that blocks internalization without trusted evidence,
  external baseline clarity, downstream source target, metrics schema, and
  budget/policy permission.
- Lineage-aware memory exports so future planning can see external dependence,
  failed external methods, rejected proposals, and internal candidates.
- Tests with toy external/downstream repositories only.

## Data Model

Add `.vibe/research/lineage/` with:

- `external_assets.jsonl`
- `relations.jsonl`
- `internalization_decisions.jsonl`
- `framework_proposals.jsonl`
- `internalization_audits.jsonl`
- `memory.md`

External assets should record source, purpose, credibility, license/use
restrictions, dependency mode, replacement plan, and provenance.

Relations should connect external assets, scout findings, hypotheses,
experiments, evidence, internal proposals, implementation candidates, and
baseline comparisons.

## Commands

Add generic CLI surfaces:

- `vibe lineage add-external-asset`
- `vibe lineage link`
- `vibe internalization propose`
- `vibe internalization readiness`
- `vibe internalization memory`

All commands should be dry, local, and file-backed. They should not generate
project-specific source code.

## Gates

Readiness for `shadow_internal` requires:

- trusted evidence or qualifying scout evidence;
- explicit external baseline asset;
- downstream `src/` target;
- metrics schema or expected evidence schema;
- remaining upside;
- budget/policy allowance;
- no missing source/license/provenance blockers.

Level transitions must not be free-form jumps. They should be evaluated by
evidence and policy, and should retain external baseline comparison.

## Tests

Add regression tests for:

- external asset registry and missing-source blockers;
- internalization level transition checks;
- structured decision/proposal validation;
- readiness blocked without trusted evidence, baseline, or downstream target;
- lineage memory includes dependencies, internal candidates, failures, and
  rejected proposals;
- shadow internal keeps external baseline comparison.

## Commit Criteria

Before committing 0.9.0:

- update version metadata and `CHANGELOG.md`;
- run targeted lineage/internalization tests;
- run full pytest;
- stage only 0.9.0 files and commit.
