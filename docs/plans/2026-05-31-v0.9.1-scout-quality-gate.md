# VibeResearch 0.9.1 Scout Quality Gate Plan

## Purpose

This plan implements `docs/todos/TODO-v8.md`. Scout evidence must become
deep-research-grade input, not a loose pile of links. Findings should be
triaged, scored, linked to hypotheses/failure modes, converted into explicit
claims, and prevented from triggering experiments when quality is weak.

The implementation must remain generic and offline-testable with mock findings.

## Scope

0.9.1 will add:

- A scout finding schema with relevance, specificity, actionability, novelty,
  credibility, code/reproducibility, failure-mode fit, and confidence fields.
- A quality gate that classifies findings into background, candidate method,
  directly actionable, baseline reference, negative evidence, implementation
  reference, or not relevant.
- Query context generation from research memory, hypotheses, failures,
  protected metric regressions, internalization proposals, adapter capabilities,
  and open questions.
- Claim-evidence mapping with support, opposition, applicability, transfer
  limits, and suggested experiments.
- Negative evidence tracking.
- Scout audit and memo sections that separate background reading from actionable
  research progress.
- Internalization readiness integration requiring qualifying scout or trusted
  project evidence.

## Data Model

Add `.vibe/research/scout/` with:

- `findings.jsonl`
- `triage.jsonl`
- `claims.jsonl`
- `negative_evidence.jsonl`
- `queries.jsonl`
- `audit.json`
- `memo.md`

## Commands

Add generic CLI surfaces:

- `vibe scout query-context`
- `vibe scout add-finding`
- `vibe scout triage`
- `vibe scout claim`
- `vibe scout audit`

No command should require live network access. Network-backed scout can be added
later through adapters; this release focuses on schema, gates, and offline
artifacts.

## Gates

Only `directly_actionable`, `baseline_reference`, and
`implementation_reference` findings may support experiment or internalization
proposals. Background findings cannot trigger experiments alone, and not
relevant findings should not be reused.

Scout evidence can support a shadow internal proposal but cannot bypass project
experiment evidence requirements.

## Tests

Add tests for:

- generic findings downgraded to background;
- task/failure/method-specific findings marked actionable;
- strong no-code method evidence handled explicitly;
- claim-evidence map generation;
- negative evidence persistence;
- low-quality scout evidence blocked from experiment triggers;
- scout evidence supports but does not bypass internalization readiness.

## Commit Criteria

Before committing 0.9.1:

- update version metadata and `CHANGELOG.md`;
- run targeted scout tests;
- run full pytest;
- stage only 0.9.1 files and commit.
