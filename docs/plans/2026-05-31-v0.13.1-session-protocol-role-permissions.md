# VibeResearch 0.13.1 Session Protocol and Role Permissions Plan

## Purpose

This plan implements `docs/todos/TODO-v16.md`. 0.13.1 turns the 0.13.0 shared
kernel into an explicit session protocol: each Codex session role has clear
readable files, writable files, allowed actions, forbidden actions, and
budget-check obligations.

The release must avoid adding complexity by multiplying roles. The default
standing roles remain Planner, Reviewer, Compiler, Executor, and Reflector;
Scout and Archivist are optional temporary roles. Unknown roles must require
`ASK_HUMAN`.

## Scope

0.13.1 will add:

- A structured role catalog used to render `.vibe/kernel/SESSION_PROTOCOL.md`.
- Role permission validation for Planner, Reviewer, Compiler, Executor,
  Reflector, Scout, and Archivist.
- Budget-aware preflight checks for session start, long-task submission,
  revise, reflect, sleep, and resume operations.
- Low-quota behavior that prioritizes Executor checkpoint/closure, then
  Reflector result preservation, while pausing Reviewer and Planner.
- CLI inspection/check commands under `vibe kernel`.

## Commands

Add or extend generic CLI surfaces:

- `vibe kernel roles`
- `vibe kernel check-role`
- existing `vibe kernel init` should render the richer `SESSION_PROTOCOL.md`.

## Gates

- Planner may write only `draft_plan_manifest.json` or `draft_plan.md` and may
  not execute, review, or approve plans.
- Reviewer may write only `plan_review_report.md` and
  `reviewed_plan_manifest.json` and may not execute commands or fill in
  experimental results.
- Compiler may write execution manifests only from reviewed plans.
- Executor may execute accepted manifests and write result artifacts, but may
  not change scientific goals, hypotheses, failure anchors, or promotion
  criteria.
- Reflector may read results and update belief/memory/decision files, but may
  not run experiments or change scientific goals.
- Scout may create `mechanism_card.md` only, and Archivist may compact memory or
  clear WATCH debt only.
- Unknown roles or more than the protocol role set must return an `ASK_HUMAN`
  style block.
- Budget-sensitive actions must fail when no budget check is recorded.

## Tests

Add tests for:

- rendered `SESSION_PROTOCOL.md` includes role read/write/forbidden boundaries
  and budget checkpoints;
- Planner write permission succeeds for draft plans and fails for execution;
- Reviewer command execution is blocked;
- Scout and Archivist are limited to temporary-role outputs;
- unknown roles require human approval;
- low quota blocks new Planner/Reviewer work and allows Executor checkpointing.

## Commit Criteria

Before committing 0.13.1:

- update version metadata, `CHANGELOG.md`, and README docs as needed;
- run targeted kernel/session-protocol tests;
- run full pytest;
- stage only 0.13.1 files and commit.
