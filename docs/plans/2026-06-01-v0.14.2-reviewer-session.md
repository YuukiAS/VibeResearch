# VibeResearch 0.14.2 Reviewer Session Plan

## Purpose

This plan implements `docs/todos/TODO-v18.md`. The source TODO labels Reviewer
Session as 0.14.1, but release 0.14.1 is already used for the artifact-adapter
blocker hotfix from the CARE prompt. To avoid duplicating that release, Reviewer
Session is implemented as 0.14.2 and the source TODO file is left untouched.

0.14.2 adds an independent pre-execution Reviewer Session. Reviewer inspects a
Planner `draft_plan_manifest.json`, kernel state, negative memory, open debts,
and evidence ledger, then emits a review report and, only for accepted plans, a
`reviewed_plan_manifest.json`.

## Scope

0.14.2 will add:

- A structured review result with verdict `ACCEPT`, `REVISE`, `REJECT`, or
  `ASK_HUMAN`.
- Anti-laziness checks for missing failure anchors, failure-signature mismatch,
  repeated negative-memory mechanisms, smoke/metadata-only plans, missing
  progress artifacts, weak belief updates, expensive plans without MVE, and
  safety-sensitive risk.
- Reviewer outputs under `.vibe/kernel/`: `plan_review_report.md` and
  `reviewed_plan_manifest.json` only when verdict is `ACCEPT`.
- CLI commands for review and validation without executing or approving through
  the Planner itself.

## Commands

Add:

- `vibe reviewer review`
- `vibe reviewer validate`

## Gates

- `ACCEPT` requires a current failure anchor, meaningful artifact, expected
  belief update, MVE-shaped minimum experiment, and no safety block.
- `REVISE` records required changes when the plan is plausible but incomplete.
- `REJECT` records generic/repeated/lazy routes such as generic U-Net reruns or
  metadata-only smoke.
- `ASK_HUMAN` is used for safety/resource/policy risks that should not be
  decided by the framework.
- Non-accepted plans do not produce `reviewed_plan_manifest.json`.

## Tests

Add tests for:

- generic U-Net plans are rejected;
- metadata-only smoke plans are rejected;
- a new mechanism with MVE and expected belief update is accepted and writes a
  reviewed manifest;
- safety-sensitive plans produce `ASK_HUMAN`;
- review reports include traceable criteria and kernel evidence context.

## Commit Criteria

Before committing 0.14.2:

- update version metadata, `CHANGELOG.md`, and README docs as needed;
- run targeted Reviewer tests;
- run full pytest;
- stage only 0.14.2 files and commit.
