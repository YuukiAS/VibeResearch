# VibeResearch 0.14.3 Planner-Reviewer Revision Loop Plan

## Purpose

This plan implements `docs/todos/TODO-v19.md`. The source TODO labels the
revision loop as 0.14.2, but release 0.14.2 is already used for Reviewer
Session after the 0.14.1 artifact-adapter hotfix shifted the sequence. To avoid
duplicating a release, the Planner-Reviewer revision loop is implemented as
0.14.3 and source TODO files remain unchanged.

0.14.3 adds the pre-execution revision loop between Planner and Reviewer. A
`REVISE` verdict becomes a structured revision packet; Planner resubmits only
the requested fields; loop limits prevent infinite plan/review churn; and all
draft/review/revision transitions are recorded as provenance.

## Scope

0.14.3 will add:

- Structured revision packets with failed criteria, required changes, optional
  suggestions, blocking risks, evidence gaps, and resubmission deadline.
- Planner resubmission helpers that edit only allowed fields and preserve
  revision history.
- Loop-limit enforcement with automatic `REJECT` or `ASK_HUMAN` after repeated
  failed revisions.
- Revision provenance records under `.vibe/kernel/PLAN_REVISION_REGISTRY.jsonl`.
- CLI helpers for creating revision packets and resubmitting drafts.

## Commands

Add:

- `vibe reviewer revision-packet`
- `vibe planner resubmit`

## Gates

- Planner may resubmit only fields named by the revision packet.
- Every resubmission must record which required changes were addressed and which
  were not.
- Repeated unresolved blocking criteria are rejected before execution.
- Accepted plans carry complete revision history into the reviewed manifest.

## Tests

Add tests for:

- `REVISE` creates a structured revision packet;
- Planner resubmits a draft by changing only requested fields;
- unresolved blocking criteria are rejected again;
- exceeding the revision loop limit produces `ASK_HUMAN` or `REJECT`;
- accepted reviewed manifests retain revision history.

## Commit Criteria

Before committing 0.14.3:

- update version metadata, `CHANGELOG.md`, and README docs as needed;
- run targeted revision-loop tests;
- run full pytest;
- stage only 0.14.3 files and commit.
