# VibeResearch 0.9.2 Dual-Track External/Internal Portfolio Plan

## Purpose

This plan implements `docs/todos/TODO-v9.md`. VibeResearch should let external
repo experiments and internal candidates progress in parallel. External work
remains a baseline/reference/revision source while internal work advances
through shadow, hybrid, and owned-candidate stages only when evidence and policy
support it.

The release must not hardcode downstream task names or CARE-specific metrics.

## Scope

0.9.2 will add:

- Track-aware experiment metadata for `external`, `internal`, and `hybrid`.
- Track transition policy for shadow, hybrid, and owned-core-candidate
  progression.
- Parallel comparison planning against external baselines.
- Budget allocation by track from policy/config.
- Pseudo-internalization and missing design-diff blockers.
- Dual-track daily memo sections.
- Tests with toy external and internal candidates.

## Data Model

Extend research experiment/proposal artifacts with:

- `track`
- `internalization_level`
- `external_baseline_asset_id`
- `parallel_comparison_plan`
- `track_budget_class`
- `design_diff`
- `protected_metric_gate`

Add `.vibe/policies/track_budget.yaml` or extend existing policy files with
track limits and ratios.

## Commands

Add generic CLI surfaces:

- `vibe portfolio track-plan`
- `vibe portfolio compare-plan`
- `vibe portfolio track-audit`
- `vibe portfolio track-memo`

The commands should be deterministic and file-backed, with no live job
submission side effects.

## Gates

Internal candidates cannot be promoted without:

- an external baseline;
- comparable metrics;
- protected metric gate pass;
- trusted evidence;
- non-empty design diff;
- no pseudo-internalization warning;
- budget allowance for the target track.

`final_owned` remains out of scope for automatic transition in this release.

## Tests

Add tests for:

- external/internal/hybrid track creation;
- missing baseline blocks internal promotion;
- shadow internal can run but cannot replace external by default;
- protected metric regression blocks promotion;
- track budget ratio enforcement;
- pseudo-internalization detection;
- missing design diff blocks promotion;
- daily memo renders dual-track state.

## Commit Criteria

Before committing 0.9.2:

- update version metadata and `CHANGELOG.md`;
- run targeted track/portfolio tests;
- run full pytest;
- stage only 0.9.2 files and commit.
