# VibeResearch 0.10.1 Owned Optimization and Champion/Challenger Plan

## Purpose

This plan implements `docs/todos/TODO-v11.md`. Once an owned alpha exists,
VibeResearch should support systematic optimization: champion/challenger
tracking, structured ablation planning, regression suites, optimization memory,
and gradual external de-emphasis under policy.

The release should stay generic and should not encode downstream scientific
content.

## Scope

0.10.1 will add:

- Champion/challenger registry for external, hybrid, and owned candidates.
- Promotion gates based on trusted evidence, protected metrics, budget policy,
  and agent rationale.
- Structured ablation planner with hypothesis, expected effect, metric target,
  protected-metric risk, and rollback plan.
- Regression suite records for smoke, metrics schema, artifact output,
  protected metrics, and champion comparison.
- Optimization memory to prevent repeated failed ablations unless new rationale
  is supplied.
- Policy-controlled gradual external de-emphasis while preserving periodic
  external regression baselines.

## Data Model

Add `.vibe/research/optimization/` with:

- `champions.json`
- `challengers.jsonl`
- `ablations.jsonl`
- `regression_suites.jsonl`
- `optimization_memory.jsonl`
- `external_deemphasis.jsonl`

## Commands

Add generic CLI surfaces:

- `vibe optimize champion`
- `vibe optimize challenger`
- `vibe optimize ablation`
- `vibe optimize regression`
- `vibe optimize memory`
- `vibe optimize external-deemphasis`

Commands should evaluate and record policy decisions, not silently promote
candidates.

## Gates

Promotion requires trusted evidence and protected metric pass. Ablations without
hypothesis, expected effect, metric target, risk, and rollback are blocked.
Failed regression suites block larger-stage experiments. External exploratory
budget can only be reduced when policy and rationale allow it, and external
baseline regression must remain scheduled.

## Tests

Add tests for:

- champion/challenger promotion;
- protected metric regression blocks promotion;
- ablation missing hypothesis blocks;
- repeated failed ablation produces memory warning;
- regression suite failure blocks larger experiment;
- external baseline retained as periodic regression.

## Commit Criteria

Before committing 0.10.1:

- update version metadata and `CHANGELOG.md`;
- run targeted optimization tests;
- run full pytest;
- stage only 0.10.1 files and commit.
