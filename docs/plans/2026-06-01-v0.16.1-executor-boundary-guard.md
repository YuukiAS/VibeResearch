# VibeResearch 0.16.1 Plan: Executor Boundary Guard

Source TODO: `docs/todos/TODO-v23.md`

## Purpose

Harden the Executor entrypoint so it can only run reviewed, compiled,
evidence-producing execution manifests. The guard should reject bypassed review
approval, weak artifacts, safety-policy violations, and incomplete stop/fallback
contracts before any command is executed.

## Scope

- Add a Boundary Guard in the Executor framework that runs before
  `run_execution_manifest`.
- Verify `reviewed_plan_manifest.json`, Reviewer verdict, revision history, and
  compiler output are consistent.
- Reject weak expected artifacts such as README summaries, repo clones, import
  success markers, cache paths, or metadata-only outputs.
- Enforce safety red lines for data permission, Slurm budget, upload/delete
  prohibitions, external data use, resource caps, and required human approval.
- Require stop condition, fallback command, and failure report path before
  execution.
- Keep behavior generic; do not encode CARE-specific runtime actions or execute
  any CARE round.
