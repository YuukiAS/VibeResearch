# VibeResearch 0.12.0 Long-Run Reliability and Soak Plan

## Purpose

This plan implements `docs/todos/TODO-v14.md`. 0.12.0 is a reliability-focused
soak release rather than a large new feature release. It should help real
downstream projects run VibeResearch continuously and expose long-run problems
in scheduler state, memory, budget, memo generation, adapter evolution,
dogfood, and external/internal dual-track workflows.

The release must stay generic and must not embed CARE-specific behavior.

## Scope

0.12.0 will add:

- A long-run reliability report that checks scheduler consistency, active job
  evidence, stale blockers, queue/run state agreement, budget drift, memo
  freshness, adapter evolution, dashboard exports, and dual-track health.
- A soak checkpoint artifact that can be appended over time and compared across
  days.
- A recovery recommendation layer that points to existing safe commands without
  automatically cancelling jobs or modifying downstream source code.
- Dogfood-friendly self-checks for the framework's own `.vibe/` state.

## Commands

Add generic CLI surfaces under `vibe reliability`:

- `vibe reliability report`
- `vibe reliability checkpoint`
- `vibe reliability compare`
- `vibe reliability doctor`

## Gates

- The doctor should flag stale active jobs, state/queue conflicts, stale
  blockers, missing memo/report freshness, budget overrun risk, adapter
  contract drift, and missing dashboard exports.
- Recommendations must be explicit and operator-approved; no live job
  cancellation or submission happens from reliability commands.

## Tests

Add tests for:

- stale active/submitted mismatch detection;
- stale blocker detection;
- budget drift and memo freshness warnings;
- checkpoint creation and comparison;
- doctor outputs safe recovery commands only.

## Commit Criteria

Before committing 0.12.0:

- update version metadata and `CHANGELOG.md`;
- run targeted reliability tests;
- run full pytest;
- stage only 0.12.0 files and commit.
