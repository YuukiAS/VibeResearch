# VibeResearch 0.10.0 Owned Framework Alpha Plan

## Purpose

This plan implements `docs/todos/TODO-v10.md`. VibeResearch should be able to
create a downstream owned-framework alpha scaffold only after an approved
framework proposal exists. The scaffold is project-owned code in the downstream
repo, while VibeResearch only supplies generic generation, audit, contract, and
adapter mechanisms.

No project-specific model logic should be added to VibeResearch itself.

## Scope

0.10.0 will add:

- Owned framework scaffold generation into downstream `src/<framework>/`,
  tests, docs, config, evaluation hooks, metrics export hooks, and adapter
  capability drafts.
- Binding between scaffold files and approved framework proposals.
- Owned framework contract checks: import, config parse, dryrun, metrics export,
  artifact output, and baseline comparison hook.
- Shadow execution metadata for owned alpha runs.
- Design-to-code audit for proposal alignment, undeclared dependencies, hidden
  external-core calls, schema-compatible metrics, and artifact provenance.
- Adapter support for internal src capabilities.
- External baseline retention after owned alpha creation.

## Commands

Add generic CLI surfaces:

- `vibe owned scaffold`
- `vibe owned contract`
- `vibe owned shadow-plan`
- `vibe owned audit`

Scaffold generation must fail if it would overwrite user code or violate
downstream `AGENTS.md` constraints.

## Gates

Scaffold generation requires:

- approved framework proposal;
- downstream framework name;
- allowed target path under downstream repo;
- linked hypothesis, external evidence, scout claim or trusted experiment,
  design rationale, and external baseline;
- no overwrite risk.

Internal capabilities cannot become active until contract checks pass.

## Tests

Add tests for:

- scaffold generation;
- no overwrite of user files;
- AGENTS.md deny constraints;
- proposal missing blocks scaffold;
- shadow execution planning;
- internal capability contract;
- hidden external core call prevents owned-core marking;
- internal metrics schema validation;
- external baseline comparison retained.

## Commit Criteria

Before committing 0.10.0:

- update version metadata and `CHANGELOG.md`;
- run targeted owned-framework tests;
- run full pytest;
- stage only 0.10.0 files and commit.
